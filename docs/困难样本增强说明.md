# 困难样本增强说明

> 更新日期：2026-05-19

---

## 一、模块用途

本模块用于基于困难样本评估集，生成增强训练样本，扩充训练集中复杂语言现象的覆盖率。

当前实现为**本地模板增强**（template_generator），仅用于代码闭环验证。后续可替换为大模型 API 生成更高质量的增强样本。

---

## 二、增强流程

```
data/hard_eval/hard_test.csv
        │
        ▼
[1] generate_augmented_samples.py  →  data/augmented/augmented_samples.csv
        │
        ▼
[2] filter_augmented_samples.py    →  data/augmented/augmented_samples_filtered.csv
        │
        ▼
[3] build_augmented_train.py       →  data/augmented/train_augmented.csv
```

---

## 三、增强样本字段说明

### augmented_samples.csv（生成阶段）

| 字段 | 说明 |
|---|---|
| source_id | 来源困难样本 id |
| source_text | 来源原始文本 |
| aug_text | 增强后文本 |
| label | 情感标签（与原文一致） |
| hard_type | 困难类型 |
| gen_method | 生成方式（template / llm_api） |

### augmented_samples_filtered.csv（过滤阶段）

在上述字段基础上增加：

| 字段 | 说明 |
|---|---|
| quality_pass | 是否通过质量过滤 (True/False) |
| filter_reason | 未通过原因（空/empty_text/too_short/too_long/invalid_label/same_as_source/duplicate） |

### train_augmented.csv（合并阶段）

| 字段 | 说明 |
|---|---|
| id | 原始样本为数字 id，增强样本为 aug_0, aug_1, ... |
| text | 文本 |
| label | 情感标签 |

---

## 四、质量过滤规则

1. 去除空文本
2. 去除重复 aug_text
3. 过滤长度过短（< min_text_len）或过长（> max_text_len）
4. 检查 label 只能是 0 或 1
5. 过滤和原文完全相同的样本

---

## 五、使用命令

### 生成增强候选

```powershell
conda run -n CK python scripts/generate_augmented_samples.py --config configs/augmentation.yaml --input_file data/hard_eval/hard_test.csv --output_file data/augmented/augmented_samples.csv --target_per_type 20
```

### 质量过滤

```powershell
conda run -n CK python scripts/filter_augmented_samples.py --input_file data/augmented/augmented_samples.csv --output_file data/augmented/augmented_samples_filtered.csv --min_text_len 4 --max_text_len 256
```

### 构造增强训练集

```powershell
conda run -n CK python scripts/build_augmented_train.py --train_file data/processed/train.csv --aug_file data/augmented/augmented_samples_filtered.csv --output_file data/augmented/train_augmented.csv
```

---

## 六、注意事项

1. **当前 template_generator 是本地模板增强，只用于代码闭环验证。**
2. **llm_generator 是大模型增强接口，支持 dry-run 和真实 API 两种模式。**
3. dry_run=True 时不调用真实 API，不消耗 API Key，返回模拟结果。
4. API Key 通过环境变量读取（OPENAI_API_KEY），不写入配置文件。
5. 真实 API 调用前需要人工确认，避免意外消耗额度。
6. LLM 输出还需要经过 quality_filter 质量过滤和人工抽检。
7. 增强样本只加入训练集，不允许出现在 dev/test/hard_test 中。
8. 不要把 dry-run 模拟结果作为最终正式实验结论。
9. train_augmented.csv 不修改原始 data/processed/train.csv。

## 七、LLM 增强命令

### dry-run 模式（不调用真实 API）

```powershell
conda run -n CK python scripts/generate_llm_augmented_samples.py --config configs/augmentation.yaml --input_file data/hard_eval/hard_test.csv --output_file data/augmented/llm_augmented_samples_dryrun.csv --target_per_type 2 --dry_run
```

### 真实 API 模式（需要设置环境变量）

```powershell
set OPENAI_API_KEY=your_key_here
set OPENAI_BASE_URL=https://your-api-endpoint
conda run -n CK python scripts/generate_llm_augmented_samples.py --config configs/augmentation.yaml --input_file data/hard_eval/hard_test.csv --output_file data/augmented/llm_augmented_samples.csv --target_per_type 20
```
